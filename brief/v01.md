# Student Pocket Manager – Full Product Brief

## 1. Product Goal

Build a personal finance tracker for students that helps them monitor cash flow between income, savings, spending, and transfers. The app should support both:
- simple left-to-right financial flow
- a more realistic graph view showing how money moves across different accounts and categories

The system should also support:
- Google login
- CSV export
- per-node inspection/history
- account overview and transaction log
- parent monitoring (optional but useful)

---

## 2. Main Users

### Student
- Records income
- Records expenses
- Tracks transfers between accounts
- Views total balance, income, and expenses
- Understands where money goes
- Uses simple and realistic views depending on need

### Parent
- Logs in with Google
- Sees student activity
- Reviews overall balance and transactions
- Monitors spending categories and transfers
- Optionally tracks multiple students under one parent account

---

## 3. Core Idea

This app is not a simple budget app. It is a flow-based money tracker.

Money should be represented as flowing through nodes, where each node is a point of movement:
- income sources
- wallet/pocket accounts
- bank accounts
- expense categories
- transfer actions

The user should be able to switch between:
1. Simple mode
2. IRL mode

---

## 4. App Modes

### Mode A: Simple View
A clean linear left-to-right flow:
- Income
- Pocket / Bank
- Expense

This mode is suitable for quick understanding and beginner-friendly views.

Example:
- Allowance
- Freelance
- Pocket
- Food
- Transport
- Shopping

---

### Mode B: IRL View
A realistic network graph showing money moving between:
- parent income sources
- pocket balances
- bank accounts
- e-wallets
- expense categories
- transfers between accounts

Example:
- Mom → Pocket A
- Dad → Pocket A
- Freelance → Bank B
- Pocket A → Food
- Pocket A → Transport
- Pocket A → Bank C
- GCash → Shopping

This mode should feel closer to reality, with messy but understandable edges.

---

## 5. Core Node Types

The app should support these node categories:

### 5.1 Income Node
Represents money coming in.

Examples:

- Side business

- Other income

Node fields:
- id
- label
- type: income
- value / amount
- date
- note
- source party
- linked account

---

### 5.2 Account Node
Represents an account or wallet where money is stored.

Examples:
- Pocket A
- Pocket B
- Bank A
- Bank B
- GCash
- Savings
- Cash

Node fields:
- id
- label
- type: account
- current balance
- account type
- linked user
- notes

---

### 5.3 Expense Node
Represents money spent.

Examples:
- Food
- Transport
- Shopping
- Entertainment
- Learning
- School
- Other

Node fields:
- id
- label
- type: expense
- category
- amount
- date
- note
- linked account
- product breakdown (optional)

---

### 5.4 Transfer Node
Represents movement of money between accounts.

Examples:
- Pocket A → Bank C
- GCash → Pocket B
- Bank A → Savings
- Pocket A → Transfer to another wallet

Node fields:
- id
- from_account
- to_account
- amount
- date
- note
- status

---

### 5.5 Expense Detail Node
This is a nested detail layer under an expense event.

Example:
- Food
  - Roti × 2
  - Coffee × 1
  - Total = Rp 45.000

This can be collapsed by default and expanded on demand.

Node fields:
- parent expense id
- product/item name
- quantity
- unit price
- total
- date

## 6. Node Interaction Model

Every node should be clickable.

### Desktop / Tablet
When a node is selected:
- show a right-side inspector panel / sidebar
- panel contains:
  - node title
  - total amount
  - current balance
  - transaction history
  - input sources
  - output destinations
  - list of related records

### Mobile
When a node is selected:
- open a bottom sheet or popup modal
- show the same detail data in a compact layout

---

## 7. Node Detail Table

The sidebar or popup should include a table with these columns:

- date
- change value
- value after change
- diff
- input source
- output target
- node assigned

Example:
- 2026-09-10 | +200000 | 250000 | +200000 | Mom | Pocket A | Pocket A
- 2026-09-12 | -50000 | 200000 | -50000 | Pocket A | Food | Food
- 2026-09-12 | +100000 | 300000 | +100000 | Bank C | Pocket A | Pocket A

This is the “financial history of this node”.

---

## 8. Node Flow Logic

Money should be traceable.

Each transaction should record:
- from node
- to node
- amount
- timestamp
- category
- description
- whether it is income, expense, or transfer
- related account or source

Example:
- Mom → Pocket A
- Pocket A → Food
- Bank A → Pocket B
- GCash → Transport

A node can have:
- multiple inputs
- multiple outputs
- a running balance

---

## 9. Realistic Flow Behavior

Not all money flows are simple. The app should support:
- multiple incomes into same account
- account to account transfers
- one account sending money to multiple destinations
- one expense being paid from different sources
- multiple transactions over time

This means the graph must not be a fixed simple tree. It should support network-like connections between nodes.

---

### Goal

### Features
- timeline scrubber

- animated connection flow
- total balance changes over time
- money stack animation for income and expense totals

### Example
- left side: income stack rises
- right side: expense stack falls
- middle: flow graph changes over time
- history updates dynamically as the timeline moves

## 15. CSV Export

The app must support CSV export of all data into a single file.

### Export behavior
- Export all records of the current selected view
- Export current filtered/query dataset
- Export in one CSV file
- File should include all transactions and associated details

### CSV format
Columns:
- date
- type
- amount
- category
- source node
- target node
- description
- note
- account
- user
- parent/student relation

Example row:
date,type,amount,category,source_node,target_node,description,note,account,user
2026-09-10,income,200000,allowance,Mom,Pocket A,Weekly allowance,,"Pocket A","Student A"

### Export flow
- Button: Export CSV
- Export all data for logged-in user
- If parent is viewing student data, export the linked student data
- File name format:
  - student-pocket-export-YYYY-MM-DD.csv
